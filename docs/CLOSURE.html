Two drop-list items were dropped in silence — §8's own prohibition

C6 · Testing one assumption the project ran on

Every project inherits a rule it never questioned. Full working in C6_Inherited_Assumption_Tested.md.

The assumption

“UI-driving days cost roughly 3.5× more tokens per hour than offline days.” Carried in CLAUDE.md as a standing justification for the no-clicking rule.

The result — withdrawn

cache_read_per_hour is only comparable between sessions of the same working mode. A session that spends its time waiting on a human is not cheap per hour because it is efficient; it is cheap per hour because the hour is mostly waiting. The scale-free quantity is cache-read per turn, and on that measure the difference the claim asserted does not survive.

The no-clicking rule itself stands. Its real justification is correctness and safety — a click cannot be diffed, reviewed, or re-run — not cost. The rule keeps its force and loses an argument it never needed.

A hypothesis about a cost anomaly in Session 6 was also written into a tool docstring as fact before being tested, and refuted by the very next control run. The docstring now carries the refutation, including the turn on which the claim was wrong.

The split-session hypothesis, tested on this project's own data

The column does not rise: 204,882 → 205,323 → 320,794 → 233,059 → 228,648. Four of five sit in a 205k–233k band; the outlier is Session 3 — the longest session, not the latest. If the driver were accumulation across sessions, 6 and 7 would be the expensive ones.

Not falsified, and not confirmed. Five points with two holes is a shape, not a test.

A confound that cannot be removed from this data: Sessions 1 and 3 ran on Opus and the rest on Sonnet, and _cost/session-NN.json records no model field — so the routing cannot even be verified from disk, let alone controlled for. Recorded as a defect in the instrument, not as a result.

Two blind spots this analysis found in its own instrument

Context compaction truncates the transcript. Every long session's snapshot has silently been a tail. Same family as the “largest of N candidates” basis line corrected earlier the same day: a number that looks like a total and is not one.

Subagent tokens appear in no snapshot ever taken. Reported separately, never folded in — folding them in would silently change what every historical snapshot's numbers mean. And the subagent output figure is refused rather than printed: 572 / 287 / 796 tokens across 43 / 31 / 96 records, against the Agent tool's own returned 203,865 / 126,839 / 301,047.

Six controls frozen at _controls/cost_tool_compaction_subagents.txt, including a floor proving the false-positive control actually parsed records. A figure that cannot be reconciled is not published as a figure; the discrepancy is published instead.

The most expensive thing in this project cannot be priced

It was not a build. It was the mirror blocker — one .set-or-replace on a table whose OneLake mirror was already live, which cost the measure load, cost export checkpoint E3 its scheduled session, and made Phase 6 run capacity-bound against a contract that said it would not.

Sessions 4 and 5 are the two that carried it, and they are the two whose cost data is gone.

That is the strongest argument in this document for the snapshot discipline the tool exists to enforce.

Measured mid-session; it did not survive

The publish gate passed eight dead links, and its reason for doing so was a good one applied one step too far. check_rebuild_materials.py deliberately does not fetch external URLs — neither the sandbox nor the device VM has egress, and a network check here would be a check that never runs and always reports a pass. But “we do not fetch them” had become “we do not look at them at all”, and a Pages link into the repository being published is the one external link that is fully checkable offline: its URL path maps to a file in the very tree being gated. Five README links, the portfolio card and the publish instructions all pointed at …/meridianpay-rti-fabric/guide.html while the file sits at docs/guide.html.

The rule that now catches it, and the one it could not be

The check resolves every Pages link into this repository against the file tree, and fails when no single candidate serving folder — root or /docs — resolves them all. Verified both ways: the pre-fix state trips it, the fixed state passes clean. Three new self-test controls, thirteen in total.

It deliberately stops short of asserting which folder Pages actually serves, because that is configuration this repository cannot see. What it does instead is force the ambiguity to be closed in writing — RUN_THIS_TO_PUBLISH.md now names the folder.

The general shape, for the next project: when a check declines to verify something, write down which part it declines to verify. “We cannot reach the network” does not license “we will not read the string”. The offline-checkable part of an unverifiable claim is usually most of it.

A fourth instrument, caught a different way

The first Session 8 cost snapshot was taken with a stale copy of capture_session_cost.py — the pre-fix version, sitting in the container's staged mirror while the fixed one sat on the device. It wrote a snapshot with no partial flag, no compaction record and no subagent count. It looked perfect. Caught by reading the JSON for the three fields Skill 11 says to read, not by anything the tool printed.

Why this one is different from the other three

Three instruments in this project were caught reporting unearned passes by being wrong: a linter that walked nothing, a query checker resolving against its own DDL, a scrubber flagging its own redaction. Each was fixed in the file.

This one was caught by being the wrong copy — and not one of those three fixes addresses it, because every fix was made in a file rather than in whatever the command line actually resolves to.

A tool that was fixed is not the same as a tool you are running. The snapshot was rewritten with the correct binary and the discarded one is not in _cost/.
